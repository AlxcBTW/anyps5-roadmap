17 Known gaps in the data
  • PPSA00000 is a placeholder title ID and names no title; reports that use it are skipped.
  • Title names, engines and stages are mined with keyword rules per line; negation and context are handled only roughly.
  • Mined chain order is a heuristic: the latest recorded stop first, then issues by creation date.
  • Read: issue, PR and discussion bodies, their comments and discussion replies, PR reviews and review-thread comments (up to 100 threads and 50 comments per thread), and timeline cross-references. Not read: commit messages, diffs, attached logs and screenshots (images, gists, uploaded files), edit history, and bot comments.
  • Issues and PRs closed more than 60 days ago are not read, even when they hold the last report on a title.
  • Stops are read from a fenced log only when the comment names exactly one title ID; the last error line in the block counts as the stop.
  • “N reports on main” counts distinct GitHub accounts whose text puts the title at that stage on main. It cannot tell whether two accounts tested the same build, and text without a stated build counts as main in issues and as the PR branch in PRs.
  • Titles without a PPSA or CUSA ID (some homebrew) appear only when curated.
  • Title IDs are joined into one game only on a person's word, one PlayStation Store concept, or names that agree once spelling, symbols, editions and known short forms are set aside. A title ID the PlayStation title list does not know, under a name written differently, stays a game of its own until someone lists it in data/games.json.
  • Covers come from the PlayStation Store or Steam; homebrew and delisted titles have none.
  • Discord reports are invisible unless someone copies them into GitHub or the curated file.
  • Signatures are matched by prefix after hex addresses and long numbers are masked; reworded messages split into separate keys.
  • PM4 status reads Pm4::UnsupportedReason(); a packet can pass that check and still be handled only partly.
  • Stages mined from PR text describe the PR branch (build “PR #N”), not main, unless the sentence says main and names no patches; they count once the PR is merged.
  • An issue that names seven or more titles is treated as a tracker: only its per-title stop rows count, as separate blockers.
  • HLE “named in issues” counts any mention of a missing function, including lists of imports that were never reached.
  • A mined stage of Menus or higher on main is only a claim until a person reviews it. What is reported off main (open PRs, local patches, a working group's stack) is shown as the stage off main and never counts.
